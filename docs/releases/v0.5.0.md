## 更新内容

- 项目与 GitHub 仓库统一命名为 shipin，重写 README、部署和服务管理说明。
- Go module、命令、管理脚本与 systemd 模板统一使用 shipin；新配置使用 SHIPIN_*，保留旧变量作为兼容回退。
- 发布产物改为 shipin-linux-amd64、shipin-linux-arm64 和 SHA256SUMS，Go 与 Python 更新器同步使用新仓库和新资产名。
- systemd 模板写入实际服务名和系统作用域，自定义 unit 的网页更新不再误查默认服务。
- 修复快速安装校验缺项或格式错误时未可靠中止的问题。
- 资源站及更新检查的上游故障使用网关错误状态，参数和业务校验保留 400。
- 设置页首次读取配置前禁用表单，避免尚未加载的配置覆盖用户输入。
- 流水线检查正式资产集合，在草稿和公开后分别下载校验并与构建结果逐字节比较。

## 升级注意

这是改名后的首个版本。旧更新器固定校验原仓库路径和旧资产名，首次迁移需使用本版本新版 shipin-service.sh 与 shipin-update.py，或校验后手动更换程序，不能直接依赖旧网页更新入口。

既有服务可保留原 unit 和程序路径，通过 SHIPIN_SERVICE_NAME、SHIPIN_SYSTEMD_SCOPE、SHIPIN_BINARY 显式指向。网页更新需要在服务进程环境中设置实际 unit 名与作用域。

JSON 状态、已下载媒体、.moviehub/ 暂存目录和 .moviehub.json 收据继续兼容，不要因项目改名搬迁媒体或改写任务中的绝对路径。升级前备份数据、程序和 unit；详细步骤见仓库 docs/service-management.md。

发布只更新 GitHub 仓库与 Release，不会自动修改生产服务器。
